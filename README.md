# World of Gophers 🐹

**Telegram-бот-RPG:** пользователь заводит героя, выполняет квесты и растёт в уровнях.
Игра построена вокруг изучения Go — и написана как полигон для самого Go:
каждая новая игровая механика приносит новую тему языка, от интерфейсов
до конкурентности и graceful shutdown.

## Идея

Проект решает две задачи сразу. Снаружи это игра: герой, опыт, золото, характеристики,
квесты, боссы и серии дней. Изнутри — учебный стенд, где каждая глава игры соответствует
этапу разработки и конкретной теме Go, а «босс» в игре — это закрытый этап в коде.

Игровой дизайн и план разработки описаны до начала кода:
- [`docs/game-design/`](docs/game-design/README.md) — механики: герой, квесты, достижения, боссы, навыки, валюта;
- [`roadmap/`](roadmap/00-overview.md) — девять этапов разработки, у каждого цель,
  текущее состояние кода, задачи и критерий готовности.

## Что уже работает

- Регистрация игрока по `/start`: новый пользователь создаётся в БД и получает приветствие,
  существующий — свою карточку с уровнем, опытом и золотом.
- Хранение игроков в PostgreSQL: пул соединений `pgxpool`, идемпотентное создание схемы
  на старте, таймауты на каждый запрос.
- Конкурентная обработка сообщений с ограничением числа одновременных обработчиков.
- Корректное завершение по `SIGINT`/`SIGTERM`: новые сообщения не берутся,
  уже взятые доводятся до ответа.
- Unit-тесты обработчика на фейковых зависимостях.

## Технические решения

**Конкурентность с ограничением.** Каждое сообщение обрабатывается в своей горутине,
но не больше четырёх одновременно — семафор на канале. Счётчики «в работе» и «обработано»
живут в `atomic`, чтобы их можно было читать из любого места без гонок.

**Graceful shutdown.** При сигнале остановки цикл перестаёт принимать обновления,
а взятые в работу сообщения намеренно отвязываются от отменённого контекста
(`context.WithoutCancel`) и получают собственный дедлайн: пользователь дождётся ответа,
даже если бот в этот момент выключается. Ожидание ограничено пятью секундами —
дальше бот завершается и пишет в лог, сколько обработчиков бросил.

**Интерфейсы вместо конкретных типов.** Обработчик зависит не от `*pgxpool.Pool`
и не от `*tgbotapi.BotAPI`, а от узких интерфейсов `PlayerStore` и `MessageSender`.
Соответствие реальных типов интерфейсам проверяется на старте, а в тестах
вместо базы и Telegram подставляются фейки — тесты не требуют ни БД, ни сети.

**Разделение ошибок по типу.** `context.Canceled` только логируется (пользователю уже
некуда отвечать), таймаут и остальные ошибки логируются с разным уровнем и превращаются
в понятное сообщение в чат. Ошибка «игрок не найден» — отдельный тип `ErrPlayerNotFound`,
а не `nil`-проверка, и обрабатывается через `errors.Is`.

**Тесты без базы, сети и реальных пауз.** Семь тестов обработчика проверяют оба сценария
`/start`, ошибки хранилища, отмену и таймаут контекста. Поведение со временем тестируется
через `testing/synctest` — виртуальное время вместо реальных пауз, поэтому проверка
двухсекундного дедлайна выполняется мгновенно и не флакает.

## Стек

| Слой | Технологии |
|---|---|
| Язык | Go 1.26 |
| БД | PostgreSQL 17, `pgx/v5` + `pgxpool`, чистый SQL без ORM |
| Telegram | `go-telegram-bot-api/v5` (long polling) |
| Инфраструктура | Docker, docker compose (бот + БД с healthcheck) |
| Качество кода | `go vet`, `golangci-lint`, тесты с `-race`, Makefile |

## Архитектура

```
cmd/bot/main.go       — сборка зависимостей, цикл обновлений, graceful shutdown
internal/
├── config/           — чтение BOT_TOKEN и DATABASE_URL
├── database/         — пул pgx, схема, SQL-запросы, доменные ошибки
├── bot/              — обработка сообщений; зависит только от интерфейсов
└── models/           — доменная модель Player
```

Поток данных: `main` читает конфиг → поднимает пул к Postgres и создаёт схему →
входит в цикл обновлений Telegram → каждое сообщение уходит в отдельную горутину
и обрабатывается в `bot.HandleMessage` через интерфейс хранилища.

## Запуск

1. Клонировать репозиторий:

```bash
git clone https://github.com/moritys/world_of_gophers.git
cd world_of_gophers
```

2. Создать `.env` в корне:

```
BOT_TOKEN=токен от @BotFather
DATABASE_URL=postgres://user:password@db:5432/wog?sslmode=disable
```

3. Поднять бота вместе с базой:

```bash
make up        # docker compose up -d --build
make logs      # логи бота
```

Для локальной разработки: поднять только базу и запустить бота на хосте —

```bash
make db-up
make run
```

Все команды — `make help`. Проверки перед коммитом — `make check`
(форматирование, `go vet`, линтер и тесты с детектором гонок).
