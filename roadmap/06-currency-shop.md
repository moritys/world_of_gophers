# Этап 06 — Валюта и магазин

Связано с игровым дизайном: [`Валюта`](../docs/game-design/07-currency.md).

## Цель

Золото уже начисляется за квесты и боссов (этапы 02–04) — теперь нужно, чтобы его можно
было на что-то потратить: титулы, роли, рамки профиля, ранги.

## Текущее состояние

`Gold` уже есть в структуре `Player` и начисляется. Тратить его пока негде.

## Задачи

1. **Таблица `shop_item`** (`id`, `name`, `price`, `kind`) и **таблица `player_item`**
   (что именно куплено конкретным игроком — `player_id`, `item_id`, `purchased_at`).

2. **Каталог товаров** (можно в коде, как с квестами):
   ```go
   var ShopItems = []ShopItem{
       {ID: 1, Name: "Титул «Backend Novice»", Price: 100, Kind: "title"},
       {ID: 2, Name: "Рамка профиля «Золотая»", Price: 250, Kind: "frame"},
   }
   ```

3. **Команда `/shop`** — список товаров с ценами; **команда `/buy <id>`** — покупка.

4. **Атомарная покупка через транзакцию БД.** Это ключевой момент этапа: списание золота
   и добавление предмета должны либо выполниться оба, либо ни один — иначе можно получить
   ситуацию "золото списалось, а предмет не добавился" (например, если бот упал между двумя
   отдельными запросами).
   ```go
   func BuyItem(ctx context.Context, pool *pgxpool.Pool, playerID, itemID, price int) error {
       tx, err := pool.Begin(ctx)
       if err != nil {
           return fmt.Errorf("begin tx: %w", err)
       }
       defer tx.Rollback(ctx) // если Commit не вызван — откатится; после Commit это no-op

       res, err := tx.Exec(ctx,
           `UPDATE player SET gold = gold - $1 WHERE id = $2 AND gold >= $1`,
           price, playerID)
       if err != nil {
           return fmt.Errorf("deduct gold: %w", err)
       }
       if res.RowsAffected() == 0 {
           return fmt.Errorf("недостаточно золота")
       }

       if _, err := tx.Exec(ctx,
           `INSERT INTO player_item (player_id, item_id) VALUES ($1, $2)`,
           playerID, itemID); err != nil {
           return fmt.Errorf("add item: %w", err)
       }

       return tx.Commit(ctx)
   }
   ```

## Go-концепции

**Транзакции (`pool.Begin` / `tx.Commit` / `tx.Rollback`).** Транзакция — это способ
сказать базе данных "выполни несколько запросов как одну неделимую операцию". Если между
`Begin` и `Commit` произойдёт ошибка — вызывается `Rollback`, и все изменения внутри
транзакции отменяются, будто их и не было. Паттерн `defer tx.Rollback(ctx)` сразу после
успешного `Begin` — стандартная идиома в Go с `pgx`/`database/sql`: если до `Commit` дело
не дойдёт (в том числе из-за `return err` где-то посередине), откат случится сам благодаря
`defer`. Если `Commit` всё же был вызван успешно — последующий `Rollback` от `defer`
просто ничего не делает.

**`fmt.Errorf` с `%w`.** `%w` — специальный глагол форматирования, который "оборачивает"
исходную ошибку, сохраняя к ней доступ через `errors.Is` / `errors.Unwrap` дальше по стеку
вызовов, при этом добавляя человекочитаемый контекст ("deduct gold: connection refused"
вместо голого "connection refused"). Это стандартная практика для всех функций, которые
возвращают `error` в Go — оборачивать ошибку с указанием, на каком шаге она возникла.

**`RowsAffected()`.** Способ узнать, сколько строк реально затронул `UPDATE`/`DELETE`, без
дополнительного `SELECT`. В примере выше это использовано как компактная проверка "хватило
ли золота": если `WHERE gold >= $1` не нашло подходящую строку — значит, обновление не
произошло, и `RowsAffected() == 0`.

## Готово, когда...

- `/shop` показывает каталог, `/buy <id>` списывает золото и выдаёт предмет.
- Попытка купить дороже, чем есть золота, не проходит и не портит данные (баланс не уходит
  в минус, предмет не начисляется).
- Купленный предмет виден в профиле игрока.
