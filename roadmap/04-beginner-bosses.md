# Этап 04 — Начальные боссы

Связано с игровым дизайном: [`Боссы`](../docs/game-design/04-bosses.md) (раздел
"Начальные боссы").

## Цель

Начальные боссы — Переменные, Циклы, Функции, Структуры, Указатели — это проверка базовых
знаний Go. Забавный момент: ты будешь писать код (проверяющий знание циклов и функций)
как раз используя эти самые циклы и функции — хорошая тренировка "в моменте".

## Текущее состояние

Никакой системы боссов ещё нет. Есть квесты и ачивки (этапы 02–03), которые дают XP —
боссы будут устроены похоже, но с "испытанием" перед наградой, а не мгновенным зачётом.

## Задачи

1. **Тип `Boss`**:
   ```go
   type Boss struct {
       ID       int
       Name     string
       Tier     string // "beginner", "intermediate", "elite", "raid"
       XPReward int
   }
   ```

2. **MVP-вариант (рекомендуется начать отсюда): самопроверка на честность.**
   Бот присылает вопрос-квиз по теме босса, игрок отвечает текстом, бот сверяет с
   правильным ответом. Никакой настоящей "песочницы" для запуска кода игрока на этом
   этапе не нужно — усложнение с реальным запуском кода можно отложить.
   ```go
   type Question struct {
       Text          string
       CorrectAnswer string
   }

   var VariableBossQuestions = []Question{
       {Text: "Как объявить переменную x типа int со значением 5 через var?", CorrectAnswer: "var x int = 5"},
       // ...
   }
   ```

3. **Состояние "игрок сейчас сражается с боссом".** Так как Telegram-бот получает
   сообщения по одному, а квиз — это несколько сообщений подряд (вопрос → ответ →
   следующий вопрос), нужно где-то хранить "на каком вопросе игрок сейчас находится".
   Для одного пользователя на сессию бота достаточно `map[int64]*BossSession` в памяти:
   ```go
   var activeSessions = make(map[int64]*BossSession)

   type BossSession struct {
       BossID       int
       QuestionIdx  int
       CorrectCount int
   }
   ```
   Обрати внимание — это хранится **в памяти процесса**, а не в БД: если бот перезапустится
   посреди боя с боссом — прогресс потеряется. Для начальных боссов это допустимо; если
   важно переживать рестарт бота — прогресс боя стоит тоже класть в БД.

4. **Победа над боссом** → начислить XP, попытаться выдать ачивку (переиспользуй
   `CheckAchievements` из этапа 03 с событием `EventBossDefeated`), убрать сессию из карты.

5. **Защита от гонки данных.** `map` в Go **не потокобезопасна** — если два апдейта от
   Telegram обрабатываются одновременно (несколько горутин), одновременное чтение/запись
   в `activeSessions` может привести к панике программы. Варианты: обернуть доступ к карте
   в `sync.Mutex`, либо использовать `sync.Map`. Подробнее конкурентность разберём на
   [этапе 07](07-intermediate-bosses-backend.md) — но сам факт "делить общее состояние между
   горутинами напрямую нельзя без синхронизации" полезно запомнить уже сейчас.

## Go-концепции

**Карты (maps).** `map[int64]*BossSession` — структура данных "ключ → значение", здесь
ключ — Telegram ID игрока, значение — указатель на его текущую сессию боя. Важно:
обращение к несуществующему ключу не паникует, а возвращает нулевое значение типа
(для указателя — `nil`), поэтому перед использованием стоит проверять `session, ok := activeSessions[userID]`
(двухзначная форма чтения из карты, где `ok` — "ключ реально был").

**`sync.Mutex`.** Мьютекс — это "замок": `mu.Lock()` перед доступом к общим данным,
`mu.Unlock()` после (часто через `defer mu.Unlock()` сразу после `Lock()`, чтобы точно
не забыть разблокировать). Пока в проекте один процесс бота и апдейты по факту
обрабатываются последовательно в `main.go` (`for update := range updates`), острой
необходимости в мьютексе ещё нет — но полезно знать, где именно она появится, если
позже вынести обработку апдейтов в отдельные горутины ("параллельно отвечать нескольким
игрокам сразу").

**Указатели в map (`map[int64]*BossSession` vs `map[int64]BossSession`).** Указатель здесь
удобен, потому что позволяет менять `QuestionIdx` внутри сессии без пересохранения всей
записи в карте (`session.QuestionIdx++` работает сразу на объекте в памяти). Если бы карта
хранила значения, а не указатели, пришлось бы читать структуру, менять поле и класть
обратно в карту явно (`s := activeSessions[id]; s.QuestionIdx++; activeSessions[id] = s`).

## Готово, когда...

- Есть минимум один рабочий начальный босс (например "Переменные") с 3–5 вопросами.
- Игрок может начать бой командой (например `/boss 1`), отвечать текстом, получить XP и,
  если применимо, ачивку за победу.
- Повторные попытки не позволяют бесконечно фармить одну и ту же победу без causa
  (продумай хотя бы простое правило: например, повторно можно проходить, но повторной
  ачивки не будет — она уже выдана).
