# Этап 05 — Серия дней (streak)

Связано с игровым дизайном: [`Серия дней`](../docs/game-design/06-streaks.md).

## Цель

Механика "стрика", как в Duolingo: считаем подряд идущие дни активности, и потеря стрика
должна ощущаться болезненнее, чем потеря опыта — так задумано в дизайне.

## Текущее состояние

Ничего похожего пока нет — ни хранения даты последней активности, ни счётчика подряд идущих
дней.

## Задачи

1. **Добавить в игрока поля**: `CurrentStreak int`, `LastActiveDate time.Time` (или
   отдельная таблица `player_streak`, если не хочется раздувать основную таблицу —
   на твой выбор).

2. **Логика обновления при любом взаимодействии с ботом** (проще всего — в начале
   `HandleMessage`, до разбора конкретной команды):
   ```go
   func UpdateStreak(last time.Time, now time.Time, streak int) int {
       lastDay := last.Truncate(24 * time.Hour)
       today := now.Truncate(24 * time.Hour)

       switch today.Sub(lastDay) {
       case 0:
           return streak // тот же день — стрик не меняется
       case 24 * time.Hour:
           return streak + 1 // ровно следующий день — стрик продолжается
       default:
           return 1 // пропустили день(-и) — стрик сбрасывается на 1
       }
   }
   ```
   Обрати внимание: `Truncate(24 * time.Hour)` работает предсказуемо только в UTC — если
   важно считать "дни" по локальному времени игрока, а не по UTC, потребуется учитывать
   часовой пояс (см. ниже про `time.Time` и таймзоны). Для MVP можно осознанно считать всё
   в UTC и явно это задокументировать в коде комментарием — это нормальное первое решение.

3. **Достижения за стрик** — переиспользовать систему из этапа 03: событие
   `EventStreakUpdated` с текущим значением стрика, проверка "== 7", "== 30" и т.п.

4. **Показать стрик в профиле** (`/start` / отдельная команда `/profile`), с огоньком 🔥
   как в дизайне.

## Go-концепции

**Пакет `time`.** `time.Time` — это тип для момента времени в Go, `time.Now()` — текущий
момент. У `time.Time` **всегда** есть привязанная таймзона (в отличие, например, от
"наивных" дат в некоторых языках) — это то, из-за чего разработчики регулярно спотыкаются:
`time.Now()` возвращает время в локальной таймзоне процесса, а после сохранения в
PostgreSQL (тип `timestamptz`) оно нормализуется в UTC. Практический совет: либо всегда
явно приводить к UTC перед сравнением (`t.UTC()`), либо всегда работать в UTC и не
смешивать — но не оставлять это "как получится".

**`Truncate` и `Sub`.** `Truncate(d)` округляет время вниз до кратного `d` — удобно, чтобы
"обнулить" часы/минуты/секунды и сравнивать только даты. `a.Sub(b)` возвращает `time.Duration`
— разницу между двумя моментами; `time.Duration` — тоже отдельный тип (не просто число
секунд), с которым можно сравнивать через готовые константы (`24 * time.Hour`).

**`switch` без явного `break`.** В Go, в отличие от C/JS, каждый `case` в `switch`
автоматически не "проваливается" в следующий — `break` не нужен (если специально не
написать `fallthrough`). Это часто удобнее, чем читать длинные цепочки `if/else if`.

## Готово, когда...

- При обращении к боту в новый день (относительно последнего визита) стрик +1, при пропуске
  дня — сбрасывается на 1, в тот же день — не меняется.
- Стрик виден в профиле игрока.
- Хотя бы одна ачивка привязана к стрику (например, за 7 дней подряд).
